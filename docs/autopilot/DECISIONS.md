# DECISIONS

- **2026-11-12 — Architecture:** Static root `index.html` with plain CSS and JavaScript ES modules; no npm packages, build step, trackers, network services or remote assets.
- **2026-11-12 — Safety:** Treat Markdown raw HTML as untrusted text, escape content and HTML attributes, and allowlist link protocols. All source drafts stay in localStorage. Exported HTML is self-contained without executable scripts.
- **2026-11-12 — Directionality:** The English application chrome stays LTR; user-authored rendered block text, each list item and each table cell gets independently resolved direction, using `dir="auto"` and first-strong-character behavior. Code remains legible with appropriate isolation.
- **2026-11-12 — Parallel development:** v1/v2/v3/v5/v6 may proceed independently in disjoint files. v4 and v7 are deliberate integration barriers; v8 is the release gate.
- **2026-11-12 — Git workflow:** Commit directly to existing `autopilot` only; no PR, new branch or fork; refresh the head and avoid overwriting concurrent work.
- **2026-11-12 — v1 direct-file entry:** Use a deferred classic `src/app.js` script with an isolated scope instead of static ES-module imports for the initial browser entry, because Chromium blocks local `file://` module fetches in common configurations. Pure parser and other core files can remain ES modules; v4 integration will need to preserve direct-file behavior.
- **2026-11-12 — v2 parser contract:** Export `renderMarkdown` and its alias `markdownToHtml` as pure HTML-fragment functions. Emit a deliberately restricted HTML vocabulary; never pass through raw HTML. Escape text and attribute values; allow only `http`, `https`, `mailto`, fragment and relative hrefs, rejecting active schemes, protocol-relative links, controls and common encoded obfuscations. Unsafe link labels render as safe text without an anchor. Use Node 22 `node:test` without npm packages; v4 owns app integration and per-block text direction.
- **2026-11-12 — v2 review fix:** Percent-encoded `/` (`%2F`, case-insensitive) is valid inside HTTP(S), relative, and fragment links; do not reject it merely because it is percent-encoded. Continue to reject active/unknown schemes, protocol-relative URLs, control characters and other existing dangerous URL patterns. Node 22 regression tests cover both acceptance and safety.
- **2026-11-12 — v3 first-strong direction contract:** `firstStrongDirection(text)` returns `rtl`, `ltr` or `null`, ignoring punctuation, digits and combining marks but honoring Unicode letters and LRM/RLM/ALM directional marks. `classifyParagraphDirection(text)` resolves no-strong-character input to `ltr` deterministically, matching the English LTR UI; v4 applies independent `dir="auto"` to user-authored blocks rather than forcing the interface RTL.
